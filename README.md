# 夜航对齐台

把歌词接到**另一版伴奏**上的对齐工作台。歌词时间来自参考版，目标版可能
开头多几拍、整体速度不同、多一遍副歌、少一段间奏——这些情况都必须先被
听见、再被确认，而不是被线性拉伸悄悄抹平。

## 本地启动

```sh
npm ci
npm run dev
```

在浏览器打开 Vite 输出的本机地址。麦克风需要本机地址或 HTTPS。

```sh
npm test          # 规划器 / 歌词解析 / 存档快照，含真实音频样例
npm run typecheck
npm run build
```

## Docker 启动

```sh
docker compose up --build
```

打开 <http://localhost:8029>。可以通过 `NIGHT_SESSION_PORT` 指定其他端口。

## 工作方式

**导入**：参考版音频、目标版音频、带 `[mm:ss.xx]` 标记的 LRC。三份文件都
先完整读取、解码、分析，全部成功后才替换当前工程；中途点「中止导入」不会
留下半个工程。

**对应点**：在参考版听到某句，按「在参考版选对应点」；界面切到目标版同一
位置，听到后按「在目标版选同一点」。两点成对写入，随后被锁定。拖动或修改
一个对应点时，其它对应点的 `source` / `time` 原样保留，其它句子的落点也
不随之漂移。

**交替试听**：「交替试听本句」把同一句在参考版与目标版间来回播放，中间自动
切换版本；循环是显式开关，选句不会偷偷打开循环。

**映射状态**（逐句可见）：

| 状态 | 含义 |
| --- | --- |
| 已确认 | 起点就是确认过的对应点 |
| 推算 | 落在两对应点之间，声学与推算位置一致 |
| 变速 | 已确认整段内容不变、仅速度不同 |
| 候选 | 声学指向别处，或同词段落有多个相近位置；只提供试听，不占位 |
| 待确认 | 两端有对应点，但本句在目标版没有声学匹配；疑似删减，绝不拉伸 |
| 已删 | 用户已确认所在段落被删；歌词保留待核对 |
| 无映射 | 只有一端有对应点，或完全没有对应点 |

**重复副歌**：候选只登记、不落位；排序与重叠检查保证后一遍不会顶到前一遍
的位置上。声学相近的多个位置会在本句面板里列成候选，逐个试听后再选用。

**删减判定**：两端对应点之间若有一段句子全无匹配，时间轴与句子面板会把这段
标成「疑似删减」，可以分别试听删减前后与整段。确认删减后，这段歌词标为
「已删」并保留原词；确认「只是速度变化」则按两端的歌速整段映射。尚未确认的
段落不会被任何一边的对应点拉伸吞掉。

**发布与继续校对**：「发布校对结果」冻结当时的歌词、对应点、删减判定与每句
的目标时间。发布后可以继续改；旧录音始终按录制时的目标歌时播放、按当时的
歌词文字显示，因此重新校对不会让历史录音对不上词。

## 双版小样

`scripts/generate-alignment-samples.py` 用纯 Python 生成两版小样，覆盖片头
弱起、整体变速、重复副歌，以及带两句歌词的删减间奏：

- 参考版 52.000s / 120 BPM：`public/samples/align-reference.wav`
- 目标版 57.857s / 112 BPM：`public/samples/align-rehearsal.wav`

```sh
python3 -I scripts/generate-alignment-samples.py
```

生成的工程数据在 `src/features/align/model/demo-project.json`，真值片段在
`scripts/alignment-fixture.json`，`tests/fixture-audio.test.ts` 直接对两段
音频做声学匹配来验证上述行为。

## 结构

- `src/features/align/lib/mapping.ts`：确定性映射规划器（对应点、删减/变速、
  候选、重叠与顺序保护）
- `src/features/align/lib/features.ts` / `match.ts`：chroma 分析与非对称声学匹配
- `src/features/align/lib/archive.ts`：IndexedDB 工程、录音与发布快照
- `src/features/align/model/`：工程状态、双版播放器、目标版时钟录音
- `src/features/align/ui/`：时间轴、句子面板、检查器、发布面板、导入对话框
